# HOME ダッシュボード

`npm start` またはデスクトップの SAKUSURA から起動すると `/home` が開きます。講義を指定しない `/` もHOMEです。`/?lecture=<slug>`、`/player`、録画URLの動作は従来どおりです。

HOME、ライブラリ、編集、デザインは共通のメニューから移動できます。Ctrl+Kの検索では「HOME」「ホーム」「ダッシュボード」でHOMEが見つかります。右上の通知ベルと設定、プログラム更新通知も共通です。外観は設定のライト・ダーク・システム、アクセント色に従います。

HOMEはライブラリや編集画面と同様に画面全幅を使い、PCでの外側余白は24pxです。左の主領域に講義の状態と最近の講義、右に進行中の作業と音声利用枠を配置します。幅が狭い場合は縦に並び替えます。大きな紹介バナーや上部の紹介ブロックは表示しません。「最近取り込んだ講義」がまだないときは、ファイルを受け取るマスコット「サク」と案内文をカード内に表示します。取り込んだ講義がある場合は一覧を表示します。ライブラリへの画面切り替えはヘッダーに集約しています。

最終更新時刻と「更新」ボタンはヘッダー右側にあります（本文の上に専用の行は置きません）。講義の状態は完成率のバー（完成件数÷全講義）と一文の要約の下に、「制作中 — 対応が必要」（画像・音声・検証待ち）と「完了」（完成・書き出し済み）の2グループで並べます。対応が必要で1件以上あるカードは左端に状態色の線が付き、0件は数字を薄く表示します。カード下の補足は次の作業（例：音声の生成が必要）です。最近の講義は行全体が編集画面へのリンクで、日付の横に状態チップ（画像待ち・音声待ちなど）を表示します。取り込み履歴がないときは「最近取り込んだ講義」を細くし、サクを縦に置きます。進行中の作業で要確認・起動確認が必要なものは注意色の枠と「講義を開いて確認」リンクで目立たせます。音声の集計方法の説明は「集計について」を開いたときだけ表示します。

## 4つの区画

1. **進行中の作業**：`/api/jobs` の実行中の音声生成・動画書き出し、および講義ごとの `images/ORCA_TASK.json` を表示します。画像生成には架空の進捗率を付けず、準備中・制作中・起動確認が必要・要確認などの状態を出します。講義名から編集画面へ移れます。
2. **音声生成の利用枠**：設定中のモデルの本日の記録と残り回数、次のリセット時刻を表示します。別モデルの記録がある場合もモデル別に表示します。
3. **講義の状態**：下表に従って自動判定し、最初は件数だけを表示します。項目を押すとその状態の講義一覧が開き、同じ項目をもう一度押すと閉じます。別の項目を押すと一覧を切り替えます。「閉じる」ボタンや一覧内でのEscapeでも閉じられます。自動更新や手動更新でも開閉状態を保ちます。最初は5件、「さらに表示」で最大10件ずつ増やし、長い一覧はカード内でスクロールできます。
4. **最近の講義**：ライブラリの `updatedAt` 順の6件と、`lectures/<slug>/share.json` の `importedAt` 順の6件を表示します。取り込みがないときは空状態を示します。`inbox:false` でも取り込み履歴があれば表示します。書き出しただけで `importedAt` がない講義は含めません。

| 状態 | 判定 |
| --- | --- |
| 画像待ち | スライド・フロー段階・人物紹介で参照する画像ファイルがない、または空 |
| 音声待ち | 空原稿、音声がない、または `planTts` と共通の入力ハッシュ・WAV整合性・発話検出で未準備 |
| 検証待ち | `reports/<slug>/harness.json` がない、不合格、講義JSONより古い、またはファイル検査に失敗 |
| 完成 | 画像・音声・検証の待ち状態がすべてない |
| 書き出し済み | `exports/<slug>_NNN.mp4` が存在（3桁以上の連番） |

状態には重複があります。書き出した後に原稿を変えた講義は、「書き出し済み」と「音声待ち」の両方になります。書き出し済みは最新原稿との一致を保証する表示ではありません。ごみ箱の講義は `libraryStore.snapshot()` によって除外し、`demo:true` も件数・一覧から除外します。

HTML単体講義は内蔵の音声・画像を外部TTSの対象にせず、`html-deck.json` と `slides.html` の両方より新しい合格レポートを検証条件にします。講義を押すと `/html-slides?name=<slug>` が開きます。取り込み情報はHTML講義も同じ `share.json` を読みます。

## 手動で完了・確認済み

自動判定では片付かない講義・作業を、HOMEから手で片付けられます（ユーザー指定・2026-11-08）。記録は `library/home-marks.json` に保存し、`lecture.json` は変更しません（変えると検証や画像依頼の照合が崩れるため）。

- **完了にする**：画像待ち・音声待ち・検証待ちの一覧の各行にあります。無音で作った講義など、待ち状態のままでよい講義を「完成」として数えます。一覧の上の「N件をすべて完了にする」で、その状態の講義をまとめて完了にできます（確認ダイアログあり）。
- 完了にした講義は「完成」の一覧で「手動で完了（自動判定：音声待ち）」のように元の状態を示し、「戻す」で自動判定に戻せます。
- 完了にした**後で講義を編集すると**（`lecture.json`、HTML講義は `html-deck.json`・`slides.html` の更新時刻が新しくなると）、自動判定に戻ります。直したあとの音声・検証漏れを見逃さないためです。
- **確認済みにする**：進行中の作業で要確認になった画像生成（`images/ORCA_TASK.json` の失敗・起動不明など）に付きます。押すとその表示を消します。同じ依頼（`jobId`）の同じ状態だけを隠すので、状態が変わったり新しい依頼を出したりすると再び表示されます。
- API：`POST /api/home/mark`（`{ name, done }`）と `POST /api/home/job-check`（`{ name }`）。スタジオの画面からの要求だけを受け付けます。

## TTS回数の記録

`tools/lib/gemini.mjs` の音声生成用 `interactions` リクエストの直前に1回を記録します。CLIとサーバーの `generateTts` はともにこの経路を使います。キャッシュ使用、生成予定の確認、ボイス一覧の取得、キー未設定での中止は数えません。接続失敗を含むAPI呼び出しの試行は数えます。自動再試行は加えていません。

`reports/tts-usage.json` にモデル別・太平洋時間の日付別の記録を保存し、CLIとサーバーの同時書き込みはファイルロックと原子的置換で保護します。異常終了で残るロックは60秒で期限切れにします。不正な記録は0回へ戻さずエラーとし、APIを呼ぶ前の記録に失敗した場合は生成を止めます。

Flash-Lite TTS の表示上限は依頼仕様の100回/日です（作成者のAPIキーのプランに合わせた値。実際の上限はAPIキーのGoogle Cloudプロジェクトのプランで決まるので、違う場合は `tools/lib/tts-usage.mjs` の `limit` を直します）。上限不明の他モデルは利用回数だけを表示します。429を受けたモデル・リクエスト開始日の記録を「本日分は終了」にします。Geminiから残り回数を取得している表示ではなく、この機能導入後にSAKUSURAが記録した試行の集計です。他アプリや導入前の使用は含みません。

日付境界は `America/Los_Angeles` の0時です。次の日付への変化を探索するため夏時間の23時間・25時間の日にも対応します。画面のリセット日時は閲覧PCのタイムゾーンで表示します。APIキー、環境変数ファイル、外部APIのエラー本文はHOME用APIに含めません。

## 取得と性能

読み取り専用の `GET /api/home?view=overview` で最近の講義・取り込み履歴・画像タスク・利用枠を先に表示し、続いて `GET /api/home` で検証を終えた状態を表示します。`GET /api/jobs` は既存の作業管理と共通です。通常は30秒、作業中は5秒ごとに更新し、非表示のタブでは止めます。手動更新もできます。

WAVの検証結果は `reports/home/audio-cache.json` に保存します。入力ハッシュとWAV・メタデータのサイズ、ナノ秒単位の更新時刻が変わらない場合だけ結果を再利用します。変更された音声は共通の `inspectAudio` で再検証します。このキャッシュは削除しても再構築されます。利用回数の `tts-usage.json` は履歴なので、キャッシュとは別に保持してください。

レポート・利用回数・検証キャッシュは `docs/DISTRIBUTION.md` と既存の配布ツールの除外対象 `reports/` に置いています。HOMEのマスコット画像は `public/home-assets/saku-receive.webp`（透過WebP、約22KB）で、サーバーの配信許可一覧に登録しています。配布時には同画像を `tools/release-public-files.json` に追加してください。配布用設定は担当範囲外のため変更していません。WebPのコピーは現在の配布ツールが対応しています。今回、配布物の作成は行っていません。

## 検証

`npm test`、`npm run check`、`npm run qa:home` を使います。HOMEのブラウザ検査は別ポートのサーバーを自分で起動・停止し、実データは読み取り専用、状態別表示は固定データで検証します。PC・スマートフォン、ライト・ダーク、125%の表示、空状態、429終了、通信エラーからの復帰、状態切り替え、各画面のHOMEリンク、検索パレットを確認します。結果とスクリーンショットは `reports/home/` に保存します。
