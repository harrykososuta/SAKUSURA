# SAKUSURA ビジネスプレゼン デザイン規格

すべての講義・プレゼンの最低条件です。CSS（`src/style.css` の `#stage`）で固定し、`npm run harness -- --browser` が自動で検査します。見本は `tests/fixtures/lectures/business-design/`。

## 構成：合計12枚（`validateDeckStructure` が検査）

| 枚目 | layout | 内容 |
|---|---|---|
| 1 | `title` | サムネイル。`#演題番号`（lecture.number）を大きく表示し、題名・サブタイトル |
| 2 | `agenda` | アジェンダ。番号 01, 02 … は自動。6項目まで |
| 3〜11 | `statement` / `flow` / `figure` / `steps` / `compare` / `table` | 本編。見出しは結論の文、1枚1メッセージ。**図解はフロー図（`flow`）を1枚以上** |
| うち2枚 | `message` | **一文だけのスライド**。要所（導入・章の山場・結論の直前）に必ず2枚。連続させない。blocks は空 |
| 12 | `takehome` | Take Home Message。必ず4つ（2×2） |

動作確認用の `lectures/demo` だけ `"demo": true` で対象外です。

この枚数・並びは**講義を生成するときのルール**です。完成後に編集画面でスライドを挿入・削除・並べ替えした講義（`"slidesEdited": true`）は、枚数・並びを検査しません（[EDITOR.md](EDITOR.md)）。

## 全ページ共通の固定要素

| 位置 | 表示 |
|---|---|
| 右上 | **SAKUSURA** |
| 右下 | ページ番号（01, 02 …） |
| 左下 | 1枚目（サムネイル）の題名 |
| 左上 | eyebrow（章の名前）。任意 |

## 文字

| 用途 | サイズ | 色 |
|---|---|---|
| 見出し（h1） | **40px** 太字 | 濃いグレー `#333333` |
| 本文 | **28px** | 薄いグレー `#767676` |
| 重要キーワード（`**語**`） | 本文と同じ | 濃いグレー `#333333` 太字 |
| ラベル・補足・ヘッダー/フッター・見出しの通し番号 | 22〜24px（番号は56px細字） | `#8A8A8A` / `#333333` |

- 例外はサムネイルの題名（72px）・`#番号`（150px）と、一文スライドの一文（76px、右に人物紹介があるときは68px・重要語に淡い紺の下線マーカー）だけ。強調のための大きさです。
- 書体は Noto Sans JP（可変ウェイト：本文500・見出し700・一文800）。入っていないPCでは読みやすさ重視のUD書体 BIZ UDPゴシックで表示します。見出しとラベルは約物を詰め（palt）、本文は詰めずに読みやすさを優先します。
- 文字はグレー2階調のみ。カテゴリの色（下の配色）は線と図形にだけ使い、文字には使いません。
- 強調は1行に1か所まで。はみ出す場合は文言を削り、文字を小さくしません。

| 色 | 値 | 使う場所 |
|---|---|---|
| 背景（生成り） | `#F6F3EE` | 全ページ（全カテゴリ共通） |
| primary（濃い色） | カテゴリ別 | 左端の帯（64px）、見出し帯の上下2本線、段階・比較・Take Homeの線、比較の丸矢印、進行バー、カテゴリ名の左端 |
| accent（差し色） | カテゴリ別 | 左端の帯の細線、段階の矢印、アジェンダ番号・Take Homeの印、サムネイルと一文スライドの短い線 |
| soft / marker（淡い色） | カテゴリ別 | サムネイルの円、カテゴリ名の地、一文スライドの下線マーカー |

### カテゴリ（シリーズ）別の配色

`lecture.json` の `category` で決まります。骨格・文字色・文字サイズは全カテゴリ共通で、変わるのは線と図形の色だけです。カテゴリの一覧は `designs/category-presets.json`（デザイン画面の「カテゴリごとのデザイン設定」で追加・削除）です。組み込みの配色は `src/core.js` の `CATEGORIES` に定義でき、スライドの配色と画像の依頼書（`npm run images`）の配色の両方がここから決まります。組み込みの配色がないカテゴリは標準の配色（primary `#1E2A47` 紺 / accent `#D27D2D` オレンジ / soft `#C9D4EE` / marker `#DBE3F4`）です。

- サムネイル（1枚目）の `#番号` の上にカテゴリ名を表示します（淡いカテゴリ色の地＋濃いグレーの文字）。一覧に並んだときにシリーズを見分けるためです。
- 1つのシリーズの中で途中からカテゴリを変えません。カテゴリを増やすときは `CATEGORIES` に1行足し、この表も更新します。
- 解剖の模式図の色の意味（動脈＝オレンジ、静脈＝青、神経＝紺）は、カテゴリに関係なく共通です。

参考資料のイラストは流用せず、サムネイルは円の図形で構成します。参考資料の色付き文字（オレンジの番号・紺の見出し）は、規格に合わせてグレーに置き換えています。

## レイアウト

- 1920×1080。左端に紺の帯、本文は左184px・右140pxの余白。見出し帯の位置は全ページ同じ。
- 本編の見出しは上下2本の紺の線で挟んだ「見出し帯」にし、左に通し番号（01, 02 …、本編だけで数える）を付けます。
- カードの枠は使いません。区切りは細い罫線1本と余白です。
- 本編のブロックは4つまで。多い場合はスライドを分けます。

| layout | 使いどころ |
|---|---|
| `statement` | ラベル＋説明の要点（罫線区切りの表形式）。右側に画像（620×460）を置ける |
| `figure` | **解剖・構造の図**。左に大きな模式図（900×600）、右に要点3〜4つ。図の上に名称ラベルを重ねる |
| `flow` | **図解の標準**。手技など絵があると伝わる段階は、各箱の上部に小さな絵（`blocks[].image`、スライドの `imageSeries` に4枚共通の構図）を入れられる。紺の枠の箱（label＝キーワード、text＝一言）をオレンジの矢印でつなぐ。3〜5個。detail は箱の下の補足 |
| `steps` | 3〜4段階の並び（label に 01, 02 …）。流れを見せたいときは `flow` を使う |
| `compare` | 2つの比較。中央は細い縦線。Before→After のように変化を示すときだけ `"transition": true` で紺の丸矢印にする。手技の違いなど絵があると伝わる比較は、各列の見出しの上に絵（`blocks[].image`）を置ける |
| `table` | 表。見出し行 `columns`（2〜4列）と、行＝ブロック（`label`＝1列目、`text`＝2列目、`cells`＝3列目以降）。行は5つまで。消毒薬の比較など、項目×観点で並べると伝わる内容に使う。物の違いが絵で伝わる表は、各行の見出しの左に小さな絵（`blocks[].image`）を置ける |
| `chat` | AIとのやりとり（吹き出し2〜4つ）。左にAI（紺の丸に光の印）、右に質問者。質問は打ち込むように、AIの答えは「考え中」の点のあと1文字ずつ表示する。主に 動き多め |
| `bars` | 数値の比較（棒グラフ・2〜6行）。棒が伸び、数字がカウントアップする。強調する行だけ `highlight` でオレンジの棒。**資料にある数値だけ**を使う |
| `code` | コード（パネル1〜3枚を横に並べる）。label＝ファイル名、code＝コード（12行まで、`//`・`--` で始まる行はコメント色）、command＝ターミナルで打つコマンド、output＝結果、text＝下の説明。コードが打ち込まれ、実行結果が出る |
| `timeline` | 年表（出来事3〜7つ）。label＝年・日付、text＝出来事。軸が次の出来事まで伸び、点が光って現れる。年と出来事は軸の上下に交互 |
| `cycle` | 輪の図（ノード3〜6つ、`center` に中央の言葉）。イベントループのように繰り返す仕組み。線が次のノードまで引かれ、光の点が回る |
| `stack` | 層の図（ブロック2〜8つ、各 `row`＝1がいちばん下）。同じ row は横に並ぶ。構成図（アプリ→API→エンジン→OS）に使う |
| `message` | 一文だけで言い切る強調スライド（見出しの一文のみ。`\n` で意味の切れ目に改行） |

**本文の下のまとめの一文（`note`）**：statement / flow / figure / steps / compare / table / chat / bars の本文の下に、紺の線とオレンジの印で区切った一文（28px・濃いグレー太字・1行）を置ける。cue の target は `"note"`。スライドの結論を言い切りたいときだけ使い、多用しない。

## 全面の使い方・間隔・文字の大きさ

ユーザー指定（2026-11-05）。修正依頼で繰り返し指摘されている内容なので、最初の作成時点で満たします。テンプレート・LLMにおまかせ・`--rules free` を問わず、新規作成と修正に適用します。既存講義の一括修正は依頼があったときだけ行い、利用者が手動で整えた配置は保持します。サムネイル・扉・一文スライドは、余白で見せる構成のままで構いません。

**全面を使う**

- 本文は見出しの下からフッターの上まで使います。本文の最下端からフッターまでの空きは、本文領域の高さの1割以内が目安です。
- 内容が少ないときは、文字を大きくし、行や箱を縦に伸ばして埋めます。余白を広げるだけで埋めません。
- 数字を並べる段は左に寄せず、全幅に配置します。
- 2列のときは両列とも下端まで使います。片方だけ短いときは項目の間隔を広げて揃えます。
- 文字を基準より小さくしないと入らない内容は、スライドを分けます。逆に、余白が目立つ同じ話題の2枚は統合を検討します。

**間隔を揃える**

- ランキングやリストなど並列の項目は、行の高さを揃えます（`flex: 1 1 0` など）。
- 画像は同じ大きさの枠に収め、本文の開始位置を揃えます。画像の大きさで行の高さや本文の位置を変えません。
- 1〜2文字だけの行が残らないよう、文字サイズや幅を調整します。

**キャラクター・装飾**

- キャラクターや装飾だけの行を作りません。本文の途中に挟むと、真ん中に空きが出ます。
- 数字の段の右端や項目の横の空きに配置し、その分だけ本文の幅を詰めて、文字と重ねません。
- 小さい絵を散らして置きません。複数体は1か所に並べます。

**文字の大きさ（下限）**

出典・ページ番号・見出し上の小さなラベルは対象外です。標準テンプレートの40px・28px は従来どおりで、これは自由レイアウトを含む全講義の下限です。

| 種類 | 1920×1080基準 | `document` レイアウト（1280×720基準） |
|---|---|---|
| 本文・表 | 27px 以上 | 18px 以上 |
| 図の箱の本文 | 24px 以上 | 16px 以上 |
| 補足・注記 | 23px 以上 | 15.5px 以上 |

**トンマナを揃える**

- 同じ部品（箱・表・リスト・数字の段）は、講義内で同じ文字サイズと行間にします。
- 共通クラスで決められるものはページ指定（`.slide[data-page="N"]`）にせず、例外だけをページ指定にします。
- 1枚を直したら同じ部品を使う他のページも確認し、直さなかった場合は同じ症状のページ番号を報告します。

**スライドの統合・削除（`document` レイアウト）**

番号はスライドの順番から自動では変わらないので、次をすべて更新します。

- ツリーの `page`
- ページ番号の文字（`.pageno`）
- 扉の「N / 総数」（`.divider-page`）
- `theme.css` の `[data-page="N"]`
- 他のスライドの原稿にある「次スライド」などの参照

## アニメーション・ビルドアップ

AIの仕組みは目に見えないため、動き多め（`motion: "rich"`）では動きで見せます（`src/motion.js`）。それ以外のフロー図は既定では静かな表示です。ユーザーが動きを希望した場合は、スライドの `animation: { "type": "flow", "targets": [経路順のブロックID] }` で指定した経路だけを動かせます。下段の説明などは経路に含めず、別のcueで表示します。

### 短い動きを共通ルールにする

要素の出現は **0.25秒・下から20px・96%→100%**。イージングは `cubic-bezier(0.22, 1, 0.36, 1)` と同じ減速曲線で、音声位置から計算します。同じcueで複数項目が出るときだけ **0.09秒** ずらし、発話に合わせて個別に設定したcueは維持します。判定の✓／×は内容側で指定し、AIが成立・失敗を推測して足すことはありません。色はカテゴリの線・図形とグレーの文字を使います。

編集画面の **このスライドの設定 → 動き・ビルドアップ** で、以下を選べます。APIキー不要の「無音で動きを確認」があり、音声なしの手動送り・無音MP4でも使えます。動き多めの基本レイアウトは「おまかせ」で短い動きを使い、ほかの講義は指定したページだけ追加します。

| 選択 | 表現 |
|---|---|
| 軽快な出現（subtle） | フェード＋短い移動＋小さな拡大。配置は動かさず、標準の罫線と余白を使う |
| 矢印 → 要素（flow） | 先の箱が出た後、矢印を0.25秒で描き、到着先を0.25秒で表示。矢印は独立したSVGの層で描き、箱が見える前から線を見せる。指定したときだけ判定を0.2秒で小さく弾ませる |
| 全体を予告（preview） | 未説明の位置は薄い点線枠だけを出し、cueで中身を埋める。未来の本文は表示しない |
| 説明中に注目（focus） | 全体を表示し、説明中のcueの項目を100%・102%、ほかを35%・100%にする。切替は0.25秒。同じcueの項目は同じ説明グループ |
| 上限で停止（limit、barsのみ） | 指定した数値に上限の点線を置き、棒はそこで停止。要求値は併記して失わず、超過時に×を出す。「上限超過後に薄くする項目」に指定したものだけ35%にする |
| 動きなし（none） | cueで即時表示。文字送り・棒の伸長なども止め、MP4もカットで切り替える |

本文を選ぶと「この項目の演出」で後から付く判定を設定できます。フロー図の2項目目以降は矢印を実線／点線にし、矢印上の通過／遮断も指定できます。点線そのものの意味は教材の文脈で決めます。

回転や波紋を常時追加することはせず、既存の「考え中」や流れの光点のように、処理・経路に意味がある場面で使います。地図・円グラフ・折れ線・天秤・記事スクロール・章のストライプ転換は専用レイアウトを用意する今後の拡張です。

| 対象 | 動き |
|---|---|
| `flow`（動き多め・明示指定） | 2つ目以降は矢印（0.25秒）→到着先（0.25秒）の順に出る。全部の箱が出たあと、光の点が経路を1回流れる |
| `chat` | 質問は約14文字/秒で打ち込み、AIは「考え中」の点（0.9秒）のあと約24文字/秒で表示（それぞれ最長3〜3.5秒） |
| `bars` | cue の時刻から0.35秒で棒が伸び、数字が0から数え上がる。上限を指定したときは超えない |
| 動き多め の基本レイアウト | 要点・段階・比較・表・まとめは0.25秒の短い出現に統一。編集画面で予告枠やフォーカスへ変更できる |
| `message`・`title`（動き多め） | 見出しが短く現れ、一文の重要語のマーカーが伸びる（0.35秒） |
| `code` | 約40文字/秒でコードが打ち込まれ（最長4秒）、続けてコマンドを打ち、結果がふわっと出る |
| `timeline` | cue ごとに軸が次の点まで伸び（0.6秒）、点がふくらんで光る。最後は軸が右端まで伸びる |
| `cycle` | cue ごとに輪の線が次のノードまで引かれ、光の点が先端を走る。全部出たあと輪を閉じ、収まるだけ（最大2周）光の点が回り、通るノードが光る |
| `stack` | 層を短い出現で積み上げる |

**アイコンと画像（動き多め）**：文字の箱と矢印だけの図は分かりにくいため、図解の各ブロックに線画アイコン（`blocks[].icon`、`src/icons.js`）を付け、1講義で2〜3枚のスライドに Codex の画像（flow の段階の絵・compare の左右の絵・statement の画像）を使います。アイコンは淡いカテゴリ色の丸に、濃い色と差し色の線で描き（文字は描かない）、要点が出るときにふくらんで現れます。足りない絵柄は `src/icons.js` に1行足します。

**1枚の情報量（動き多め）**：本文（statement）は6つ、表（table）は6行、フロー図（flow）は5つまで置けます。5つ以上のときは行の余白を自動で詰めます。それ以外のシリーズは従来どおり（本文4つ・表5行）です。

- 動きはすべて音声の再生位置から計算します。停止・再開・巻き戻し・動画の書き出しで同じ絵になります。
- 動きは音声の終わりの0.2秒前までに収めます。cueがそれより遅い場合は、言及前に表示しないことを優先し、そのcueで瞬時表示に縮めます。収まらないときは `npm run check` が「最後の cue を早めて」と警告します。
- 全画面プレゼンの手動送りでは、押すたびに cue の時刻から動きの終わりまで再生して止まります。
- MP4の書き出し（`npm run render`）は、動きのあるスライドだけフェードと動きの間を1コマずつ撮影します（動きのないスライドは従来どおり）。
- 1枚に入れる動きは見せたい1点に絞ります。色は線と図形の色（`--primary` / `--accent`）だけで、文字はグレー2階調のままです。
- 見本：`lectures/ai-motion-demo`（無音リハーサルで確認。数値は表示確認用の例）。

## 画像（Codexが生成）

- 置けるのは `title`（右側の大きな挿絵。円の図形の代わり）・`statement`（右側 620×460）・`figure`（左側 900×600）。手順・因果の図解は画像にせずフロー図で作り、**解剖・構造は模式図の画像**にします。
- 解剖図の色の意味は固定：動脈＝オレンジ `#D27D2D`、静脈＝青 `#6F8FD6`（深部は破線）、神経＝紺の細い破線、骨＝ごく淡い灰青。
- 画像内に文字は描かせません。`"labels": ["上腕動脈", …]` を書くと、Codexが各構造の座標を `images/<画像名>.labels.json` で返し、スライドは紺の点と濃いグレーの文字（24px）で名称を重ねます。はみ出し・ラベル同士の重なりはブラウザ検査が確認します。
- `"checklist": [...]` には、向き（左右・親指側）・走行・分岐や合流の位置関係など、図が満たすべき解剖学的な条件を書きます。Codexは生成後に自己確認し、人も画面で確認します。
- 生成済みの画像を直すときは `"revision": "直す点"` を書き、prompt・checklist も直した内容に合わせて更新します。`npm run images` の依頼書に「修正依頼」として載り、Codexは今の画像を見本に指摘の点だけを直します。修正を確認したら `revision` を外します（残っている間は本番検証が通りません）。
- スライドに `"image": { "alt": "何を表す画像か", "prompt": "生成指示" }` を書き、`npm run images -- --lecture <slug>` で依頼書 `lectures/<slug>/images/REQUEST.md` を作ってCodexに渡します。保存先は `lectures/<slug>/images/<スライドID>.png`。
- 画風は参考デザインに合わせたフラットな線画（紺の線、オレンジ・淡い青・白の塗り）。画像内に文字を入れません。
