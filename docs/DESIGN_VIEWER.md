# デザインの閲覧と追加

`npm start` で起動し、ライブラリ右上の「デザイン」から `/design` を開きます。

- 一覧は画面幅を使い、実際の先頭スライドのサムネイルをグリッドで表示します。PDF・CSSのデザインも反映し、見える範囲から描画します。サムネイルや名前をクリック、またはフォーカスしてEnterを押すと詳細ページへ進みます。デザイン名・説明の検索と、更新順・名前順の並べ替えができます。
- 左側のフォルダーは「デザイン」「使わない」「ゴミ箱」です。サムネイルをフォルダーへドラッグして移動できます。移動できるフォルダーを点線で示し、ドロップ先を強調します。「ゴミ箱」へ落とすと削除の確認を表示し、ゴミ箱から「デザイン」「使わない」へドラッグするとその場所へ復元します。同じ場所へのドロップやドラッグの中止では保存しません。各デザインの「···」からも収納・一覧に戻す・複製・削除を操作できます。削除はゴミ箱への移動で、元のデザインやPDF素材は消しません。メニューの「復元する」では元の収納先へ戻します。ゴミ箱のデザインは通常の一覧や選択欄に出ず、直接編集もできません。標準デザインは「使わない」に収納できますが、削除はできません。
- カテゴリや講義が参照するデザインの削除は拒否します。使用中でも「使わない」への収納は可能で、参照や内容は維持されます。カテゴリごとの割り当ては一覧上部の折りたたみ欄で変更できます。
- スライドの見本・カテゴリ選択・16種類の項目切り替えは、カードを開いた先の `/design/detail?category=...&layout=...` にあります。
- 詳細は、その項目固有の配置・文字サイズ・余白・項目数・動きなどのルールと、共通のデザインを分けて表示します。
- たとえば表紙は題名72px・演題番号150px、一文は76pxと下線マーカー、フロー図は箱の間隔や線幅を表示します。数値は見本のCSS計算値です。
- デザインに設定したカテゴリの配色を切り替えられます。
- 表紙・アジェンダ・本文・一文・まとめ・フロー図・図と要点・段階・比較・表・年表・輪の図・層の図・チャット・棒グラフ・コードの16種類です。
- 選んだカテゴリとレイアウトはURLに残るので、再読み込みやリンク共有で同じ見本を開けます。
- 詳細ページは「編集する」（標準デザインは「複製して編集」）を右上に表示します。複製・AIへの調整依頼は「…」にまとめ、カテゴリで使用中のデザインと「このデザインを使う」は右側に表示します。PDFのページは見本の上の選択欄・前後ボタンで切り替えられ、表示中のページをそのまま編集できます。編集のキャンセルや保存後も、そのページに戻ります。
- 文字の見本はページに収まる大きさに縮小表示します。横のpx表記は1920×1080のスライドでの実寸です。
- 書体はスライドと同じ候補を使い、インストールされたものに従って表示します。

## 追加と編集

1. 一覧の「デザインを追加」から `/design/new` を開きます。初期画面には標準テンプレートを表示せず、PDFを選ぶ空の画面を表示します。「PDFから追加」と入口を統一しました。旧URLの `?source=pdf` も利用できます。
2. 10MB以内・1〜60ページのPDFを選び、「取り込んで編集する」を押します。PDFの配置・図版・文字を取り込み、そのPDFの編集画面へ自動で進みます。
3. 左のページ一覧から選び、PDF上の文字をクリックして文章・位置・サイズなどを編集します。名前・説明も変更できます。
4. 「変更を保存」で詳細へ移動します。一覧に戻ると新しいカードが表示されます。
5. 既存のTemplateや標準デザインから作る場合は、その詳細の「複製して編集」または「…」→「複製を作る」を使います（`/design/new?base=<id>`）。色・書体・文字サイズ・余白・カテゴリ・構成を調整でき、元のデザインは変更しません。
6. 保存済みの詳細にある「編集する」から再編集できます。標準デザインは直接変更できません。

編集画面は通常エディターと同じく、**左にページ一覧・中央にスライドの見本・右に編集スペース**を配置しています。左のサムネイルでページを切り替え、見本の見出し・本文・小見出し・表のセルなどをクリックすると、その文章を右側で編集できます。入力は即時反映され、`**重要語**` の太字記法も使えます。ブランド名の編集は全ページ共通です。配色・書体・余白・構成・AIへの依頼は、右側を下へスクロールして設定します。狭い画面ではページ一覧を横並びにし、見本の下に編集スペースを表示します。

ページを選んで編集した文章はそのページに保存します。上の「レイアウト」で見本を選んだ場合は、そのレイアウトの共通の見本文字として保存します。保存した文章は詳細画面の見本・複製・再編集にも反映されます。PDFから取り込んだデザインでも、抽出された文字をクリックして右側で編集できます。

保存先は `designs/design-<UUID>.json`、編集前のバックアップは `designs/backups/` です。ブラウザのlocalStorageではなくプロジェクト内に保存されます。同名の保存と別画面の古い版による上書きを拒否します。プレビューは変更を即時表示しますが、保存するまでファイルは変わりません。

フォルダーとゴミ箱の保存先は `designs/organization.json` です。分類を変えても元のデザイン・参照PDF・ページSVGは移動や削除をしません。分類の変更も版を照合し、編集中のデザインと競合した場合は再読み込みを求めます。`GET /api/designs?includeTrash=1` は整理画面用の一覧、`POST /api/designs` の `move`・`trash`・`restore` が整理操作です。削除とカテゴリ割り当ては同じ保存ロックで処理し、使用中の参照が切れる競合を防ぎます。

## 自由なカテゴリ・構成とAIへの調整依頼

詳細ページの「カスタマイズ・AIに依頼」から編集ページを開きます。標準デザインの場合はコピーから始まります。カテゴリ選択の横にある「＋ 追加・編集」からもカテゴリ設定へ進めます。

- カテゴリはこのプリセット内で1〜24種類。表示名・4色の配色を設定でき、最初の4種類の名前も変更・削除できます。カテゴリを削除してもほかのプリセットには影響しません。
- 「枚数とページ構成」で1〜60枚の構成テンプレートを作れます。各ページのレイアウト・用途または見出しのひな形・並びを変更し、ページの追加・削除もできます。予定尺は10〜7200秒、まとめは1〜6項目に設定できます。
- 文字サイズは全体に共通の設定と、ページ別の設定があります。見出し・本文のページ別欄を空にすると共通値を継承します。「見本」でそのページを表示し、設定を変えて見た目を確認します。大きい文字や長い文では収まりも確認してください。
- 詳細の枚数・構成図・ページごとの見本は保存した構成に従います。構成図のページを選ぶと、その用途と文字サイズを含む見本が表示されます。

そのまま「変更を保存」することも、「今の設定をAIに渡して仕上げる」で追加の希望を書き「設定を保存してAIへの依頼を作る」こともできます。依頼作成時の設定は `snapshot.json`、AIの編集対象は `preset.json`、依頼は `REQUEST.md` として専用フォルダーへ保存します。参考PDFがある場合はコピーも含めます。

依頼文をCursor・OrcaなどのAIチャットへ貼り付け、最後に依頼書の完了コマンドを実行します。結果は新しいプリセットとして登録され、待機画面がその編集画面へ切り替わります。元のプリセットは維持します。作業中は依頼した設定を固定します。「画面の編集に戻る」で待機を解除して再編集でき、作成済みの依頼書は残ります。待機URLの `aiTask` で開き直した場合も依頼時点の設定から復帰できます。

ここで編集する枚数・構成・カテゴリはプリセットの設計情報です。既存講義・音声への自動適用や、`npm run new` による講義作成へのプリセット適用はまだ実装していません。AI依頼にも、講義・図形・cue・音声・TTSを変更せずプリセットを仕上げる契約を記載しています。

## PDFの原本デザインを取り込む

一覧の「デザインを追加」で10MB以内・パスワードなし・1〜60ページのPDFを選び、「取り込んで編集する」を押します。各ページの図版・罫線・余白・文字の形を保持したデザインを保存し、そのまま編集画面へ進みます。既存の16種類のレイアウトやカテゴリ色への置き換えは行いません。AIへの依頼は、取り込んだ後に文字などを調整したい場合に使えます。

取り込み前はPDF選択の案内を、選択後は参考PDFを表示します。取り込み後はPDFのページ一覧・プレビュー・文字編集欄を表示し、一覧カードにも元PDFのサムネイルを使います。同名のデザインがある場合は別名で追加します。

編集画面では、ページの用途・並び・複製・削除と、抽出できた文字の差し替え・位置・幅・サイズ・色・表示有無を変更できます。未変更の文字はPDFの字形をそのまま使います。差し替えた文字には埋め込み書体を使い、不足する文字は端末の代替書体で表示します。既定では元の文字枠に収まるよう、指定サイズを上限に縮小します。「枠に収める」を外せば指定サイズで表示します。スキャン画像中の文字は文字データとして抽出できないため、編集項目にはなりません。図版は元の内容を保持します。PDFと縦横比が異なる画面では余白を付けて収め、伸縮しません。

元PDFは `designs/references/`、取り込んだページSVG・埋め込み書体・文字位置情報は `designs/pdf-pages/pdf-<UUID>/` に保存します。プリセットは `pdfSource` でそのPDFと各ページ・文字の変更を参照します。配布時はこの素材フォルダーと参照PDFも一緒に配布してください。

新しいPDFの変換時はローカルのPython＋PyMuPDFを使います。`PYTHON_PATH` があればその指定を優先し、未指定ならPATH上とWindowsのPythonランチャーに登録された環境からPyMuPDF導入済みのものを自動で選びます。npmパッケージは追加していません。変換済みプリセットの表示・文字編集・保存はNodeとブラウザで動き、表示時にPythonを呼びません。変換環境がない場合は理由を表示し、標準デザインへの置き換えは行いません。

以前の配色だけの取り込みを原本デザインへ切り替える場合は `npm run design:pdf -- --theme design-<UUID>` を使います。元のプリセットはバックアップされます。変換済みの場合は文字やページの編集を維持して終了します。

## カテゴリごとに使うプリセット

一覧の「カテゴリごとに使うプリセット」で、カテゴリごとにデザインを選んで「カテゴリの設定を保存」を押します。新しいカテゴリも追加できます。対応は `designs/category-presets.json` に保存します。設定を別画面で同時に変更した場合は古い版での上書きを拒否します。

詳細画面でも「『カテゴリ名』で使用するプリセット」と「この組み合わせを保存」で設定できます。カテゴリ選択を切り替えると、そのカテゴリに割り当てたプリセットを開きます。PDF原本デザインはカテゴリの配色で変更せず、選んだPDFの配置・色を維持します。カテゴリは使用するプリセットの対応として使います。講義や動画へのプリセット適用は別の連携であり、まだ実装していません。

## 実装

一覧は `public/design-gallery.html`、詳細は `public/design.html`、共通の表示は `src/design.css`・`src/design.js`。見本・説明・項目別ルールの定義は `src/design-catalog.js` で管理します。見本は `/design/preview` のiframe内で、既存の `src/style.css`・`renderSlide`・`applyMotion` を使います。動きは完了した静止状態を表示します。

追加・編集は `public/design-editor.html`・`src/design-editor.js`・`src/design-editor.css`。設定の型・検証・プレビューへの適用は `src/design-theme.js` と `src/design-theme.css`、ファイル保存は `tools/lib/design-store.mjs` で管理します。`GET /api/designs` が一覧、`GET /api/designs?id=...` が1テーマ、`POST /api/designs` が追加・更新です。保存は同一Origin・JSON・専用ヘッダーを要求し、版の照合・直列化・一時ファイルからの置換を使います。環境変数・TTS設定・任意のファイルパスは扱いません。

PDFの選択と表示は `src/design-pdf.js`、保存は `tools/lib/design-pdf-store.mjs` です。`POST /api/design-pdfs` は同一Origin・PDF形式・専用ヘッダーを要求し、サイズとPDFの先頭・終端・暗号化表記を簡易検査します。完全なPDF構文検証ではありません。UUIDで保存し、元のファイル名はメタデータに記録します。`GET /api/design-pdfs?id=...` が情報、`GET /api/design-pdfs/file?id=...` がPDF本体です。Range/HEADに対応し、取得時にサイズとハッシュを照合します。

CLI依頼の画面は `src/design-import.js`、作業保存・結果確認は `tools/lib/design-import-store.mjs`、完了コマンドは `tools/design-import.mjs` です。`POST /api/design-imports` が作業作成、`GET /api/design-imports?id=...` が状態取得です。完了コマンドでは既存のデザイン検証と保存処理を使い、作業IDに対応する固定デザインIDで一度だけ新規登録します。

カテゴリ・構成編集とAI調整依頼の画面は `src/design-customize.js` です。version 1の既存デザインをそのまま読み、任意項目 `categoryNames`（カテゴリIDと表示名）、`deck`（targetSeconds / takehomeCount / slides）、`aiInstructions`（追加の希望）を必要に応じて保存します。deck.slidesの各要素はlayout・purpose・任意のheadingSize / bodySizeです。settings.categoriesは可変のカテゴリIDと4色の対応です。deck未指定時は従来の12枚構成を表示します。通常講義の構成検証は変更していません。

配色は `CATEGORIES`、数値表示は見本の実際のCSS計算値から取得します。箱の数・コードパネル数・画像の有無で変わる数値は、その見本での値を示します。見本の文章・棒グラフの数値・図版はデザイン確認専用です。構成図の5・9枚目は標準テンプレートの一文スライド配置例です。一覧に戻ってもカテゴリを保持し、旧形式 `/design?layout=...` のリンクは詳細ページへ移動します。

検査は `npm run qa:design`。一覧がテーマカード1枚のみであること、カード全体のクリック・Enterによる詳細への移動、カテゴリを保持した一覧復帰、4カテゴリ×16レイアウト、項目別の文字サイズと表示値の一致、URL復元、無効パラメーター、PC・タブレット・スマートフォン幅、公開ファイルと講義の不変性を確認し、`reports/design/` に結果とスクリーンショットを保存します。

`npm run qa:design-editor` は複製→調整→保存→一覧→再編集をブラウザで確認し、`reports/design-editor/` に保存します。両検査は一時保存先を使い、利用者のデザインファイルに検査用デザインを追加しません。保存・入力検証・競合・バックアップ・APIの検査は `npm test` に含まれます。

`npm run qa:design-gallery` は一時保存先に18種類のデザインを用意し、PDFとCSSの実サムネイル・検索・収納・削除キャンセル・ゴミ箱と復元・使用中の保護・保存状態の再読み込み・Enter/Escapeによる操作メニュー・1906/1147/820/390/320px表示を確認します。結果と画面PNGは `reports/design-gallery/` に保存します。

`npm run qa:design-pdf` は同梱の2ページPDFで原本デザインの自動取り込み・元ページの表示・文字差し替え・複製と削除・保存・カテゴリの割り当てと切り替え・PC/スマートフォン幅を確認します。結果は `reports/design-pdf/`。データは一時保存先を使用し、外部AIの呼び出しはありません。

`npm run qa:design-customize` は独自カテゴリ・自由な枚数と構成・ページ別の文字サイズ・詳細表示・設定を含むAI依頼作成・作業中の固定と復帰・不正な結果の拒否・編集再開・完了後の自動切り替え・元プリセット保持・スマートフォン幅を確認します。AIの外部呼び出しは実行せず、一時保存先で検査用の結果を作ります。結果は `reports/design-customize/` です。

PDF原本の変換は `tools/pdf-design-export.py`、素材保存は `tools/lib/pdf-design-store.mjs`、描画と文字編集は `src/pdf-design.js` です。`GET /api/pdf-designs?id=...` がページ・文字情報、`GET /api/pdf-designs/asset?id=...&file=...` が許可したSVGと書体です。カテゴリの対応は `tools/lib/category-design-store.mjs`・`src/category-designs.js`・`GET/POST /api/category-designs` です。
